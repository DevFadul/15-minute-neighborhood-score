This file is the captured, real console output of automated test runs
against main.py (no output below has been hand-edited). Each run below
maps to one or more scenarios from the project test plan:

RUN 1 -- First launch (no data file yet)
  - View All on empty history -> graceful "No assessments yet." message
  - Delete on empty history -> graceful error, no crash
  - Compare with fewer than 2 assessments -> graceful error, no crash

RUN 2 -- Corrupted data file
  - data/assessments.json manually overwritten with invalid JSON
  - App detects the parse failure, renames the file to assessments.json.bak,
    warns the user, and continues with an empty history instead of crashing

RUN 3 -- Full feature walkthrough (18 scenarios in one continuous session)
  - Invalid main-menu inputs ("9", "-1", "abc", "") each rejected and re-prompted
  - Blank nickname rejected and re-prompted
  - Non-numeric ("abc") and negative ("-4") walking-time inputs rejected
  - Oversized walking-time input ("9999", > 180 max) rejected
  - Assessment #1 "Current Apartment": mixed tiers -> hand-verified 73.0/100 (Good)
  - Assessment #2 "Perfect Score Home": all times <=5 min -> 100.0/100 (Excellent)
  - Assessment #3 "Car Dependent Suburb": all times >25 min -> 0.0/100 (Poor)
  - Assessment #4 "Edge Test A": tier boundary values 5/6/10/11/15/16 -> 63.0/100 (Fair)
  - Assessment #5 "Edge Test B": tier boundary values 25/26/0/1/2/3 -> 69.0/100 (Fair)
  - Recommendations on a mixed-score assessment -> correct 2 weakest categories + tips
  - Recommendations on a perfect-100 assessment -> graceful "no major gaps" message
  - Recommendations on a zero-score assessment -> correct weakest-category tips
  - Compare two different assessments -> correct side-by-side table + verdict
  - Compare an assessment against itself -> rejected with a clear error
  - Edit: update one category's time -> score correctly recalculated afterward
  - Edit: rename a nickname -> change reflected immediately
  - Delete: cancelled at confirmation ("maybe" rejected, then "n") -> item still present
  - Delete: confirmed ("y") -> item removed, ID gap now visible in the history list
  - About screen -> renders live from the same constants that drive scoring
  - Long nickname (48 characters) -> truncated cleanly in fixed-width columns
    instead of overflowing into neighboring columns (this exposed and fixed a
    real formatting bug during testing -- see note at the bottom of this file)
  - Clean exit

All three runs completed with exit code 0 and zero unhandled exceptions
(verified by grepping the raw output for "Traceback"/"Exception" -- none found).

                 ABOUT SDG 11 & METHODOLOGY                 
============================================================
SDG 11 (Sustainable Cities and Communities) calls for inclusive, safe,
resilient, and sustainable urban areas with access to green space and
affordable, accessible transport. The '15-minute city' concept holds
that residents should be able to reach daily essentials within a
15-minute walk, reducing car dependency and emissions.

This tool scores a neighborhood (0-100) across 6 weighted categories:
------------------------------------------------------------
  Grocery / Fresh Food Access      weight 20
  Healthcare / Pharmacy            weight 15
  Education / Childcare            weight 15
  Public Transit Access            weight 20
  Parks / Green Space              weight 15
  Everyday Retail & Services       weight 15
------------------------------------------------------------
Each category's walking time earns a tier percentage of its weight:
  <=5 min: 100%   6-10 min: 75%   11-15 min: 50%
  16-25 min: 20%   >25 min: 0%

======================================================================
BUG FOUND & FIXED DURING TESTING
======================================================================
The initial version of print_comparison() in ui.py embedded each
assessment's nickname directly into a fixed-width (15-char) table
column header. Because Python's format specifiers only pad short
strings and never truncate long ones, a nickname longer than the
column (e.g. 'Perfect Score Home (ID 2)', 26 chars) ran straight into
the next column with no separating space, breaking the table layout.

Fix: the compare table now prints fixed 'Option A' / 'Option B'
column headers (always constant width) with the full nicknames shown
in a legend line above the table instead. A general-purpose
truncate_text() helper was also added and applied to the history-list
and score-breakdown views as a second line of defense for long
nicknames. Verified working against a 48-character nickname above.
